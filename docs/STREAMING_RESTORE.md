# 0.6.2 · 恢复边听边显示

## 用户反馈原文

> 这个版本我直接发送到手机上安装了，要28s的语音结束后才开始翻译，你还是改回上一版吧，体验不好。 那些降噪算法可以用在实时监听的地方，自由监听模式下容易被环境音打断，而且会翻译错误的环境音

本反馈优先于先前“出现后不改字”的偏好。0.6.1 用户已安装；以下不是对仍在使用 0.6.0 的假设。

## 改动边界

- `LiveDesk.record()` 恢复直接发布中间结果，不等待原文完成或整段译文完成。
- 原文确认后仍提前保存。`transcriptRows()` 合并同 ID、同方向、同原文的正在增长的译文，且只覆盖 TRANSLATING 的显示，不改写已完成/用户纠错的记录。
- 小窗和全文都显示可用的译文预览，不再用“原文已保存，正在翻译”盖住已有文字。
- 删除已被否决的 `StableCaptions` 最终发布拦截及其 8 项旧策略断言。不是为了让测试通过而降低现行要求：当前验收改为录音未停止就持续显示原文和译文。
- 保留 3.5 句子身份关联、缺时间标记排序、失败输入不能吞后段、明确空回复收尾及有界文字补译。明确身份关联迟到时仍不把译文随意配给旧句；这是正确性等待，不是最终结果门控。
- 不改模型选择、账号、音量、历史格式。安装号升为 0.6.2，可覆盖 0.6.1，不卸载、不清数据。

## 自由监听降噪分开推进

目前 Silero 是人声检测，不是去掉人声中的雨声。真实降噪限定麦克风自由监听，并检查“噪声误打断”与“噪声送进识别”两条路径；不能只提高音量阈值，不能破坏轻声句首，也不能把新算法套到屏幕播放采集里。

候选官方来源：[GTCRN](https://github.com/Xiaobin-Rong/gtcrn)、[RNNoise](https://github.com/xiph/rnnoise)、[WebRTC APM](https://webrtc.googlesource.com/src/+/refs/heads/main/modules/audio_processing/g3doc/audio_processing_module.md)。GTCRN 提供 16kHz 流式 ONNX，可复用项目现有推理库；RNNoise 参考接口使用 48kHz 并需要原生接入；APM 能提供降噪/回声等整套处理，但不能未经测试与当前回声处理重复叠加。包体和接入成本是选型依据，不代表哪一个识别效果必然更好。

本包先恢复已可用体验，不包含未验证的新降噪。手机未连接，无云端新增调用、无私人记录改动。已完成 [GTCRN 固定雨声和中法录音初筛](../evaluation/noise/README.md)：24 组混合声音有音频指标改善；未经过 Android 回声/抢话链路或真实模型听写，不能称已修复环境音。下一步独立接入自由监听并验证轻声、抢话与资源释放，最后补 Fold5 实际收音和 WhatsApp 连播。
