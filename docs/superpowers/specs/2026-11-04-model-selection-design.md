# 全功能 Qwen 模型选择

日期：2026-11-04。状态：范围已按用户反馈扩大到所有现有在线功能；本文为待用户确认的设计，尚未实施。手机版本仍为 0.5.6。

## 1. 用户原话与目标

> 我觉得你可以在设置弹窗里增加一个选模型的功能，让我自己来测试

> 其他模式的一起啊，可以一键切换所有功能的模型，也可以分功能切换模型！

提供两种并存的操作：一键使用一整套兼容的模型组合；对某个功能单独选择模型。覆盖面对面按住说话、自由监听、屏幕字幕、中文转法语，以及打字/纠错重译、朗读/重播/语音分享。不能只有设置变化而真实请求没有变化。

继续使用 Qwen。保留现有默认配置，用户主动选择后才改变新任务的模型。不恢复已删除的键盘、文件录音选择或轻声朗读功能。不改手机音量、个人历史或凭据，不扩展到通话远端注音。

## 2. 已检查的现状

- `TranslationSettings` 只保存地区、业务空间、凭据等，没有保存模型选择。
- `QwenOptions` 已有识别、文字翻译、朗读、实时模型字段，但自由监听和字幕共用实时字段。
- 面对面和中文转法语共用 `ConversationTranslator` 的识别、文字翻译流程。当前未携带功能来源，必须显式区分，不能从当前页面猜测旧任务的归属。
- `QwenLiveSession` 使用旧 LiveTranslate 协议。新模型的配置、增量文字、结束事件和音频不能只通过修改模型字符串接入。
- `ConversationVoice` 在云端朗读失败后会尝试手机语音；用户比较模型时可能误以为听到的是所选千问。
- `VoiceClips` 的键包含独立 TTS 型号，但 `LiveDesk` 把实时模型返回的音频按当前 TTS 配置存入同一缓存。这不足以区分真实生成来源，也会受到运行中设置修改的影响。
- 当前评测模块只进入测试包，不能直接作为正式应用的依赖。已验证的协议案例可作为生产适配器的测试素材。

## 3. 选择的方案与边界

采用“整套预设 + 按功能覆盖”。仅有整套预设不能满足单功能对比；只列出每个底层模型则需要用户逐个理解和调整。两层配置同时保留便利性和可控性。

“整套”是兼容组合，不是把同一个名字填进所有接口。例如 LiveTranslate 接收声音进行同传，不能替代输入纯文字的专用朗读接口。整套切换后，界面必须列出各功能的具体型号，明确哪些配套模型沿用现有选择，不声称所有请求均由一个模型完成。[LiveTranslate 3.8 能力](https://help.aliyun.com/zh/model-studio/qwen3-8-livetranslate-flash-realtime)

### 3.1 初始整套预设

下表定义目标行为，并非当前已经实现或已通过产品验收。

| 预设 | 面对面 / 中文转法语的语音输入 | 自由监听 | 屏幕字幕 | 配套文字翻译 / 独立朗读 |
|---|---|---|---|---|
| 当前方案 | Qwen3 ASR Flash → MT Flash → 按需 TTS Flash | LiveTranslate 3.5，文字与译音 | LiveTranslate 3.5，仅文字 | MT Flash / TTS Flash |
| Audio 3.1 | Audio 3.1，返回原文、译文及按需译音 | Audio 3.1 | Audio 3.1，仅文字 | MT Flash / TTS Flash |
| LiveTranslate 3.8 | LiveTranslate 3.8，返回原文、译文及按需译音 | LiveTranslate 3.8 | LiveTranslate 3.8，仅文字 | MT Flash / TTS Flash |
| Omni 3.8（实验） | Omni 3.8，返回原文、译文及按需译音 | Omni 3.8（实验） | Omni 3.8（实验），仅文字 | MT Flash / TTS Flash |

语音一体方案有完整原文与译文才能作为成功记录。不能为了使用新模型丢掉纠错需要的原文，也不能把回答问题、原样复述当作正常翻译。自动朗读关闭时只请求文字；当前已有的自由监听开关若在监听中改变，停止本机播放立即生效，云端输出设置在下次会话生效并明确提示。

本轮 Audio 3.1 和 LiveTranslate 3.8 仅有短样本证据；Omni 3.8 曾正确听写但原样返回法语，必须在选择页保留这一实验警告。不使用“最好”“最省钱”等未经同条件验证的标签。[已有证据](../../QWEN_EVALUATION.md)

### 3.2 按功能覆盖

每项均提供“跟随整套”和具体选择，显示最终生效结果：

1. 面对面语音：分步方案或四种已适配实时模型。
2. 自由监听：四种实时模型。
3. 屏幕字幕：四种实时模型，仅文字。
4. 中文转法语：分步方案或四种已适配实时模型；方向固定为中→法。
5. 文字翻译：MT Flash 或 MT Plus，作用于打字、纠错重译、分步方案和字幕异常复核的翻译阶段。语音一体方案自身的翻译不再重复调用它。
6. 独立朗读：Qwen3 TTS Flash 或 Qwen3 TTS Instruct Flash，作用于无可复用译音的重播、修改后的译文及语音分享。不做声音克隆或新增音色设计功能。
7. 分步识别与异常复核：现用 Qwen3 ASR Flash 或 Audio 3.1 ASR Flash Streaming；只影响独立识别路径，不冒充改变实时模型内部的听写器。

新增的专用候选是待适配选项，不将“官方支持”当作本账号已验收。MT Plus 支持中法；TTS Instruct 官方列出中法合成能力，但法语效果仍需双向接口验证，不能据中英文指令调节描述推断法语效果更好。[文字翻译](https://help.aliyun.com/zh/model-studio/machine-translation) · [TTS 型号与语言](https://help.aliyun.com/zh/model-studio/tts-model/)

仅提供已实现相应协议的型号，不开放任意填写模型名。某个候选尚未完成适配时可显示进度但不可选；不得把带占位选项的版本称为全功能完成。

## 4. 设置弹窗与切换规则

继续使用现有 `StudioDialog`，入口为“设置 → 千问翻译”，弹窗分为账号连接与模型方案。保持当前视觉样式，内容可滚动、操作区可见，适配合屏、展开、键盘和文字放大；选择行提供明确选中态与至少 48dp 的触控区域。

- 顶部为四个整套预设，下方展示各功能实际配置。
- 选整套预设会在弹窗草稿中一次设置全部功能并清除单项覆盖。已有覆盖时在同一弹窗内写清“保存后覆盖这些单项设置”，不叠加多层确认。
- 单项修改只影响该功能；顶部显示“自定义 · 基于某方案”。单项可恢复“跟随整套”。
- 所有修改在点“保存”后一次持久化；返回或关闭丢弃草稿，不发生一半生效。
- 开始一次按住录音时固定本次配置；文字提交、重译、重播或分享在操作开始时固定配置；自由监听/屏幕字幕在会话开始时固定。进行中的任务和同一会话的重连不因设置变化混用模型。
- 保存时如有旧任务运行，明确显示“已保存，下次开始使用；当前仍使用 ××”。不自动结束录音或屏幕共享。
- 设置变化不重新翻译旧历史。旧记录的生成来源保持不变；主动重译是新的生成操作，保留其新来源。
- 第一次升级迁移为当前方案，不触发云调用。不认识的持久化配置标为不可用并引导恢复当前方案，不能悄悄改模型继续请求。

业务空间仍由用户设置，不能硬编码账号标识。根据模型目录校验地域和地址要求，缺配置时用中文提示并禁止启动不兼容请求，不能自动换地区。[Omni 3.8 地址要求](https://help.aliyun.com/zh/model-studio/qwen3-8-omni-flash-realtime)

## 5. 模块与数据流

### 5.1 模型目录和配置解析

在生产 provider 模块建立纯 Kotlin 目录：稳定配置 ID、实际型号、用途、协议、地域/地址条件、文字/音频能力、音色与采样率配置、实验状态。预设组合与单项覆盖通过同一个解析器生成不可变的有效配置；UI、请求工厂与测试共用它，不在多个页面维护字符串列表。

持久化保存带版本的全局预设、单项覆盖及必要的朗读参数。账号设置与模型设置在同一次保存中校验并原子提交；失败不发布新内存状态。模型信息不包含密钥。未知字段可向前兼容，未知关键型号不能默默降级。

### 5.2 按功能创建服务

工厂以功能、操作/会话 ID 和配置快照为输入，提供单句翻译、实时翻译、文字翻译和朗读接口。面对面与中文转法语在任务创建时携带明确来源；不能继续让两者无条件调用同一个无来源 provider。

分步单句继续识别后翻译；一体单句使用有明确开始、提交、取消、完成上限的实时适配。上层得到统一的原文、译文、可选声音及来源信息。固定方向的按住说话不得因为换气创建多条用户消息；所有片段合并到本次按住任务，取消后迟到事件不得再保存或播放。

### 5.3 协议适配与统一事件

四种实时模型分别构造对应配置，转换为共用的连接、原文、译文、音频、结束、失败事件。共用传输与有界缓冲，但不把协议差异堆进 UI。

适配器分别处理增量与累计快照、输入/响应关联、异步结束、错误和取消。音频附带真实采样率与编码，由播放器统一转换；不能沿用旧模型固定采样率。无法确定语种或缺原文的输出显示待确认，不靠生成译文猜测后伪装成功。

自由监听的回声参考只使用实际播放的音频。抢话同时停止本机播放并使已取消响应的迟到音频失效，原文和已完成译文仍保留。字幕仅请求文字，不申请音频输出后再静音。

屏幕字幕仍边收边显示，保持全文累积和自动跟随。用户此前确认的播放来源分组、结束后两秒边界与断线补齐问题不能通过更换模型宣称解决；在本轮回归中继续记录其未完成边界。

### 5.4 真实来源与声音缓存

每次操作保存请求的型号、服务端实际返回的型号（如有）、配置版本、功能、时间、请求/会话编号及完成状态。服务端未返回实际型号时显示“请求型号，服务端未回报”，不冒充已经核实。来源元数据随记录持久化，兼容旧记录“来源未记录”；不默认保存私密录音或额外导出原文。

实时译音与独立朗读分别标明来源，缓存键使用真实生成型号、协议/音色、语言、文本版本及相关配置。自动播放复用本次任务生成的译音。手动重播和分享使用操作开始时的配置：原译音的生成方案、音色及文本均与当前一致时才直接复用，否则按当前独立朗读模型合成。独立朗读缓存也只允许相同配置命中。界面显示真实声音来源，不把新合成的独立 TTS 标成实时翻译模型的声音；不因重播而重新翻译原文。

新增配置使用严格模型选择：失败报错，不偷偷调用别的云模型或手机语音。旧的自动手机语音降级改为用户明确发起的“用手机语音朗读”重试，界面标明来源，不计作千问模型结果。字幕异常复核保留为独立、可追溯的辅助调用，界面注明复核所用模型，不冒充主模型原始结果。

## 6. 错误、费用与隐私

- 显示容易理解的错误：未配置账号/业务空间、地区不匹配、模型未开通、网络失败、服务失败、未收到完整译文；附可复制的脱敏请求编号。云服务无法区分的错误不要猜测原因。
- 同一任务只运行选定方案，禁止为比较同时并跑全部候选。只允许现有有界重试/复核，不新增无限重试。
- 切换、保存、恢复默认本身不花钱。实际使用按账号计费，模型菜单说明文本/音频差别，不给未经证明的每小时成本或节省倍数。
- 脱敏日志不保存密钥，不把地区空间标识写进源码或提交证据。声音缓存保持现有有界生命周期，不引入个人录音落盘。
- 自动云端验证沿用现有评测账本与原 10 元预算边界；未知费用不清零、不换账本绕过。用户主动在产品内使用与自动评测分别记录，不把自动评测限额冒充平台扣费上限。
- 离线常用表达仍播放随包文件，标为离线录音，不为“一键切换所有功能”而增加无意义的云调用。

## 7. 自动化验收

全部优先通过接口测试，由 AI 执行；不把逐个点模型、回听和排查交给用户。

1. **解析与持久化**：四套预设；每项覆盖与恢复；整体替换清除覆盖；迁移；非法组合；失败不提交；重启保持；凭据与其他偏好不变。
2. **实际路由**：对每个入口使用假传输断言真实请求的型号、地址、文字/音频配置及调用次数，覆盖中文转法语、重译、分享和异常复核，不只检查 UI 标签。
3. **会话一致性**：进行中修改设置不混用；重连沿用旧快照；下一次操作使用新配置；迟到回调不污染新任务；取消不播放、不保存成功记录。
4. **协议契约**：三种新实时协议及旧基线的原文/译文增量、累计快照、交错响应、双向语种、结束与超时；新 ASR/MT/TTS 的请求和返回；无声、重复事件、输出缺项不可误报成功。
5. **播放与缓存**：真实生成来源分离；换模型/音色后不能错命中；改文后不播旧文；失败没有静默手机语音；抢话、回声、耳机分路、分享和重播沿用既有要求。
6. **界面**：合屏/展开、文字放大、滚动、返回取消、保存错误、在用模型与待生效模型；所有选择可由测试接口读取和设置，UI 自动化只补充验证可见交互。
7. **云端与产品层**：有界固定样本逐项验证双向原文/译文、实际型号、可播放音频和费用证据；雨声、长停顿、长语音、停止后全文及受控抢话回归。记录失败，不跑到一次成功就宣布稳定。

发布前必须明确区分“适配完成”“短样本通过”“实验性质量问题”“尚未真机验证”。用户可选择标明风险的实验模型，但不能出现看似可用而根本没有调用适配的菜单项。

## 8. 交付次序

按同一完整范围分步实现，不缩减为只做字幕：模型目录/持久化/请求路由 → 协议与单句/实时统一接口 → 整套与单项设置 → 实际来源/缓存/错误提示 → 自动化与 Fold5 验证。

设计确认后再形成具体测试驱动实施计划。继续当前分支，不使用子代理或新工作目录；保存并提交代码、测试、README、决策/验收文档与 CI 更新。测试/提交前核对 main；目前无远程仓库，不能声称已同步 GitHub。产品更新时才修改单一来源版本号；本次仅设计，不构建、不安装、不调用付费模型。
