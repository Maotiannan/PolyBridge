# 首版实施计划

0.5.4 已完成本轮接线验收：雨声、长语音及跨应用字幕通过，轻声加底噪的回声仍失败。下一阶段先与机主确认声音处理整体方案，再实现和验收；不继续堆叠局部补丁。必须保留完整句首、正常短回复及现有雨声过滤，实际麦克风与受控注入分开测。[分项进度与下一步](NEXT_TASKS.md)

0.5.0 优先打通真实用户路径。用另一个应用播放固定法语和中文，核对同一悬浮窗中的原文、译文、受保护声音和停止行为。展开后的长按分别测试移动、越界、移回、松手和两次系统上滑。常规回归与要求个人千问凭据、真实耳机或 OriginOS 的检查分别执行。[当前进度](NEXT_TASKS.md)

需求以根目录 PRD v1.0 和启动说明为准。2026-11-03 核对的起点是两份需求文件与一份启动说明，没有现成应用和 Git 历史。首轮选择普通 Android 应用，诊断和面对面两条线共享收音实现。已授权在电脑上开发，真机安装及录音留到设备再次接入后。

首个测试用已知样本调用音频统计接口。之后用播放捕获的本应用测试音作为阳性对照。手机与单副耳机的十秒收音是下次接机的起点，通话实验以两端知情和真实听音为前提。

## 从音频样机到面对面对话

机主反馈「界面这也太粗糙了，我感觉你才完成了1%」，并确认「全都做好为止，我们可以慢慢打磨」。优先交付可在手机上试用的一段完整对话，保留 PRD 的其余验收目标。

1. 启动进入面对面。外屏单手轮流按中文或法语，内屏对坐双方各操作一半。历史和设置单独进入，设备诊断归入设置。
2. 有个人百炼凭据时，按住收音、松开识别、翻译、纠错与重播。未配置时提供可直接翻看的离线常用表达，并明确云端连接状态。
3. 自动检查两个方向的网络请求、取消、中途失败和升级恢复。构建后在 Fold5 上检查布局和入口，真实账号的语音验收与本地接口测试分别记录。
4. 以真实对话为基础继续自由监听、消息与键盘、耳机和通话专项，分别记录需要的账号、硬件和对端条件。

## 自由监听与跨应用阶段

0.4.0 先验收单副耳机的面对面体验。把播放器实际使用的出口、音量增益和播放进度与点击动作放进同一项测试。连续监听分三层验收，分别使用可重复的混合语音、真实安卓播放器、Fold5 的扬声器和机身麦克风。整库清除测试限制在专用虚拟设备。随后按微信和 WhatsApp 分别验收语音消息、通话下行和远端收到的上行译音，双耳机另外验收。

在面对面验收后，先用固定中法语音核对自由监听两种方向与返回的声音，再以相同接口跑长时间测试。手机的近场拾音、打断和系统中断另测。语音文件、编辑后插入及指定耳机分配均提供程序接口测试。微信和 WhatsApp 各自按远端收音与上行送音验收。手机重新接入时先确认外放最低档，并复测来自机身和耳机的实际路由。[当前验收顺序](NEXT_TASKS.md)
