# 0.6.1 稳定字幕与无手机回归

## 交付内容

屏幕字幕不再逐字显示猜测：模型完成原文、未触发原文异常检查时，先耐久保存，再显示原文；完整成功译文之后补齐。结束、断线或翻译失败仍保留已发布原文。模型 final 只代表识别完成，不保证正确；用户主动纠错可以修改，自动复核不能偷偷换字。

临时原文/译文仍在底层协议内部流转，自由监听保持原来的预览。字幕专用 `StableCaptions` 不影响面对面音频、耳机路由、音量或私人设置。

## 已复现并修复的链路缺陷

| 失败测试 | 修复 |
|---|---|
| response.created 及译文早于输入通知，到达时直接丢弃 | 按创建顺序有界缓存，输入到达后关联；重复不抢占下一句 |
| 明确完成且 output=[] 的回复无法结束 | 结束为 EMPTY_REPLY，进入一次补译，不永久占用待处理句 |
| 队列已有 12 句，重复 committed 被当成第 13 句 | 仅新增输入检查容量 |
| 字幕草稿随模型更新改字；取消结果含半句译文 | 只发布确认原文与成功完整译文，取消内容不显示为译文 |
| 原文直到译文完成才保存 | 原文 TRANSLATING 记录先 commit，完成时只补对应记录 |
| 异常复核重新识别后覆盖已经读过的原文 | 已确认原文仅补文字翻译；未发布的异常原文才允许原音复核 |
| Audio/Omni 800ms 与其他模型停顿不一致；关闭朗读改变断句 | 按功能选择媒体/对话等待，与输出音频开关分离 |
| 延长停顿后停止收尾仍只有 1200ms | 收尾使用同一配置并留 200ms 以上余量 |

用户补充 LiveTranslate 3.5 为可用性基线，且第三段历史也只有两个词。针对性回放发现：旧实现只按响应顺序配原文，忽略了服务端显式关联；缺失时间戳的新原文按 0 排序；前段识别失败还可能删除被暂时配给它的后段响应。现在原文与响应独立保存，优先按翻译消息的 previous_item_id 对应原文，再用输出 item_id 对应响应；有身份但关联尚未到的 LiveTranslate 响应等待关联，不冒险发布到上一句。缺失时间标记仅用递增位置维持顺序，不当作精确音频边界用于复核。失败输入不能误删未明确归属的响应。

这依据 [LiveTranslate 官方消息关联说明](https://help.aliyun.com/zh/model-studio/live-translator-server-events)，不是声纹或 WhatsApp 消息身份识别。没有 item_id 的旧协议包保留按序兼容。原文与响应各最多 12 个，单条文本上限 32000 字符，响应音频总缓存最多 4MB；超限明确失败。字幕发布层上限 32 条待译、512 个完成去重标识。历史仍保留每种模式最近一次采集的全部记录，不设 100 句截断。

## 一次补译与费用

仅屏幕字幕的确认原文遇到取消、空回复或异常译文时，调用配置中的文字翻译模型一次。原来实时模型的请求没有被假装成功；补译保留模型来源。原音不再次发送，已显示原文不改；没有无上限重试。

恢复队列默认最多 2 条，停止时最多等待 6 秒；超限/超时保留原文并明确失败。失败、排队积压和断网不是“准确率已解决”。本轮自动测试全部使用本地服务与固定虚构文本，**云端调用和新增实际费用为 0**，未改原评测账本。

Audio 3.1 使用官方支持的 `silence_duration_ms`，没有凭空添加防打断开关。[官方参数说明](https://help.aliyun.com/zh/model-studio/fun-audiochat-client-events)。加长到默认 1800ms 能减少由短停顿触发的分句，不等于已识别整条媒体来源。

## 无手机自动测试

最终结果：152 项测试全部执行通过（core 43、provider 43、evaluation 24、app 42），零失败、零跳过；Lint 零错误、31 项现有提示；0.6.1 主包和测试包构建与 APK 签名校验通过。[脱敏证据](evidence/2026-11-04-stable-captions-0.6.1.json)

- core：临时文字隐藏、确认原文先出、取消半句隐藏、撤回/复核不可改字、重连 ID 复用、容量溢出、失败/停止/迟到结果、序列化与重开。
- provider：真实本地 WebSocket 请求和回包、本地 HTTP 文字补译，提前响应、取消、重复完成、双句正确关联；四模型已有传输回归继续执行。
- LiveTranslate 3.5 基线：两路真实本地 WebSocket、连续三段重复五轮、第三段先于第二段返回、关联信息迟到，15 段完整保留；另测前段失败不能吞掉后段响应。没有用户事故的手机事件，不能宣称已确认事故唯一根因或真实云端五轮通过。
- app：Robolectric 直接调用生产 `LiveDesk.record()`，覆盖字幕稳定模式、收尾成功、意外中止及自由监听预览不变；音频输入和过滤依赖被替换，**不作为实际 ONNX 或采集设备验收**。
- app 持久化：150 句、20 秒时间戳间隔、每两句逆序完成，逐句重开，完整原文与译文按说话顺序保留。这是协议/存储回放，不是 50 分钟真实云端听写。
- 浮窗：小屏 375px 待译说明，现有长文自动跟随、手动回看、全文双语回归。
