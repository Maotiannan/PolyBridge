# 18秒中法噪声样本：实测报告

## 结论 · 2026-11-05

用户试听确认后，对同一批10段18秒样本分别运行基础过滤与自由监听降噪：电脑20组、Fold5 20组。直接向正式 `SpeechFilter` / Android `SpeechGate` 接口输入PCM，运行随包真实Silero与GTCRN模型；不是另外实现一套Python降噪来代替产品测试。

**基础过滤发现2个声学问题；开启自由监听降噪的10个场景没有触发本轮声学告警。不能概括成“软件全部通过”。**

| 场景 | 基础过滤 | 自由监听开启降噪 |
|---|---|---|
| 清晰中法、普通雨声、机械声、钟表声 | 四轮首尾指标达到门槛 | 四轮首尾指标达到门槛 |
| 雨声与人声能量接近（0dB） | 第三句句首强音样本仅保留33.67% | 四轮首尾指标达到门槛 |
| 第8秒雨声增大6倍 | 第三句句首仅保留14.50%，全句强音样本保留88.85% | 四轮首尾指标达到门槛 |
| 更低音量的人声与雨声 | 四轮首尾指标达到门槛 | 最低句首97.82%，最低句尾99.49% |
| 纯雨、纯机械声、纯钟表声 | 三段均未向识别端发送非零音频 | 三段均未向识别端发送非零音频 |

两处失败均发生在第三句法语「À quelle heure part le prochain train ?」，电脑和手机结果一致。当前屏幕字幕使用相同的基础过滤；自由监听按设置决定是否先增强。因此，本次发现的是**送到模型之前已经丢失声音的风险**，不能全归因于千问；也不能据此断言用户先前所有WhatsApp漏译都来自这个原因。本轮未改产品算法、判断门槛或模式分流。

7段含语音素材共有28次发言，开启降噪后最低全句强音样本保留99.32%、句首97.82%、句尾99.49%。长停顿后的第三、第四句话均有输出，音频总长度保持18秒。基础过滤最大缓冲220ms，增强路径236ms，没有整段等待到结束；这是本机音频缓冲，**不是字幕首字延迟**。

Fold5在不按真实时间等待的注入测试中，处理每段18秒音频耗时约1.04～1.52秒（增强模式），最慢单个20ms输入块处理5.22ms。只包含该处理接口，不包含实际收音、云端、播报、界面负载或长时间温升，不能换算为产品端到端延迟。

## 指标怎样看

- 逐句以纯净参考的强音位置检查输出是否被清零：幅度超过该句均方根的20%，且超过10个PCM单位。首尾窗口各250ms，以首个/末个强音位置定位。全句、句首或句尾保留率低于90%就记录告警；不是看到结果后为失败样本放宽门槛。
- 非零样本不代表这句话可听清、更不代表识别/翻译正确。混合噪声也可能让样本非零，所以同时记录逐句波形相似性和能量变化，不将保留率称为文字准确率。
- 纯噪声检查独立进行：任意非零样本进入识别端就记录告警。报告中的纯零输出抑制值受数值下限影响，不能解释为物理降噪达到一百多分贝，应看“非零输入为零”。
- JUnit用例强制校验素材摘要、时长、音频时钟、流式输出及关闭次数。声学结果包含失败并单独记录在 `acousticIssues`；结构测试绿灯不是声学质量全部合格。

完整逐句数据和双平台结果：[机器可读证据](evidence/2026-11-05-short-noisy-clips.json)。
