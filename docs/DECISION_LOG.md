# 决策记录

## 2026-11-03 · 雨声、换气与连续字幕

> 实时监听翻译受环境影响很大，雨声都会被识别！你要修复一下这个问题！应用监听一段语音，如果长语音中间有换气，会导致软件重新拾音好像，反正最后只剩最后一句话了。你先做，我晚点再插上手机让你测试

旧版会把持续雨声原样送到识别，两段译文先后返回的次序也会影响历史显示，浮窗只展示最近一句。0.5.2 在两种监听中默认检测人声，并按实际开口顺序保留全文。应用播放允许更长的停顿，现场对话则更快给出译文。判断灵敏度与停顿时间由应用管理，无需机主切换场景或勾选降噪。按机主安排先用固定录音和隔离安卓设备验收，接线后再验证实际千问和 Fold5 的收音。[自动验收记录](NEXT_TASKS.md)

## 2026-11-03 · 屏幕字幕与展开手势

机主要求「默认就是中法互译，所以不用选择才对吧？选择语音按键功能完全没用可以删掉，只需要从应用播放中采集！」「在其他应用听语音的时候也能实时在屏幕文字上显示原文和译文？」「从这个应用彻底移除键盘」。监听图标跟随输入电平，对外表达固定为机主说中文、应用生成法语。来源应用可以更换并记忆。

交互原文为「另外vivo在展开的状态下按住中文的说话按键会把底下的dock栏呼出来导致失败」「另外按住说话的时候手动一下就失效了，应该做一下适配，另外还有按住的时候应该可以划到一个区域外就取消且变成红色提示。跟微信那种一样。」「这个软件所有的弹窗都太原始了，交互太恶心了，要适配一下！」。应用以沉浸模式和预留空间避开系统热区，以指针位置决定松手时是否发送。应用弹窗统一适配折叠与输入法高度。[安卓沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)

机主澄清「删除轻声朗读功能，我刚刚是叫你轻一点因为我在办公室，不是说这个软件要这个功能」。0.5.0 移除轻声开关及扬声器衰减。应用用系统媒体音量播放，办公室测试沿用现场的低音量。

## 2026-11-03 · 面对面优先

机主提出「先把面对面对话的抢话和回声测好。能自己测的你就自己测，真需要第二副耳机或者另一台手机的时候再叫我。」「我点击重播没有反应，没有声音出来，我戴着耳机的现在。纠错按钮没有用！」「对话历史，特别是手机展开的时候应该尽可能的显示的多一点，紧凑一点，现在布局太松散了。」「对话历史地方新增一键清除按键。」

同一轮还问到「现在的TTS用的是什么？有没有更好的方案？或者直接用千问的TTS模型？这样是不是翻译+TTS一步到位会更好一点？」「我说的功能目前只有按住发送信息的面对面翻译可用，我一开始的提示词的其余功能你根本还没做完？！」原始五项需求及每项未完成的验收条件列在[验收进度与下一步](NEXT_TASKS.md)。

手动重播默认送到机主耳机，自动翻译继续按听众分路。校对同时展示两栏，保存人工修改与调用云服务重译分成两个动作。每句单独持有播放状态。自由监听直接采用千问同传返回的译音，按住说话保留可编辑文字及按当前文字重新朗读的能力。两者都使用千问，合成模型只负责朗读给定的文字。[实时语音翻译](https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime) · [千问语音合成](https://help.aliyun.com/zh/model-studio/qwen-tts-api)

房间轻声打断仍有漏检。下一轮以相同距离、底噪、耳机分路和最低外放音量，对比现有处理与百炼 Android 实时音频组件的内置回声消除。除了打断耗时，还要检查两句是否都保留、有没有多出回声句，以及另一方是否收到正确出口的译音。官方把内置回声消除和降噪列在 AOQ 和 WebRTC 的音频能力中，本机版本使用 WebSocket。更换朗读音色无法处理麦克风里的回声。[百炼实时音频协议对照](https://help.aliyun.com/zh/model-studio/realtime-api-overview)

## 2026-11-03 · 第一版

- 采用一个 Kotlin 核心模块和一个 Android 应用模块。先贯通实际收音、诊断和导出，平台代码按音频和界面分包。
- 编译与目标选 API 36，对齐实机。最低选 Android 12（API 31），便于统一蓝牙运行时权限、通信设备和前台服务路径。其他机型需实测。
- 诊断固定采样十秒，按住说话限三十秒，优先 16 kHz、失败时尝试 48 kHz。统计使用实际采样率。录音只在内存中累加样本数、能量和峰值。
- 播放捕获每次都请求系统授权，限定到选中的应用。先用自己的短音做对照，微信和 WhatsApp 的语音消息及通话另行验收。
- 双屏阶段保留真实按住说话和两种语言方向，固定示例标注为演示。选择真实云端供应商和地区前，需验证凭据、双向翻译、字幕及播放服务。
- 首版不需要服务器或 Docker。调试和高权限通话功能保持独立。第二部手机只作为通话验收对端。

## 2026-11-03 · Fold5 单耳机收音

0.1.0 在真机上可以从内置麦克风采样。仅向录音器指定已连接的耳机时，系统返回启动状态 -22，当时的蓝牙通话通道未打开。0.1.1 使用公开的通信设备接口选择耳机输出，等待系统确认后从配套的通信输入采样。收到有效声音仍须核对录音器报告的实际输入。已有通话时保留系统当前选择，取消、失败与正常结束都会释放本应用取得的通道。[Android 通信设备接口](https://developer.android.com/reference/android/media/AudioManager#setCommunicationDevice(android.media.AudioDeviceInfo))
## 2026-11-03 · 面对面对话与音频验证

已按机主选择将面对面设为默认。云账号由机主在本机配置，诊断不使用云服务。双向语音、打字和重播走独立接口，断网或识别不准时保留文本供校对。词本的声音在发布时合成，随应用安装。千问合成返回的 WAV 可能携带流式长度占位值，收到完整音频后按实际字节数修正，避免手机误判播放时长。

面对面选用百炼北京或新加坡地区的独立语音识别、文本翻译与语音合成接口。[语音识别](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference) · [机器翻译](https://help.aliyun.com/zh/model-studio/qwen-mt-api) · [语音合成](https://help.aliyun.com/zh/model-studio/qwen-tts-api)

## 2026-11-03 · 实时中法互译与机主的音量设置

个人账号上用受控录音验证了千问实时模型 `qwen3.5-livetranslate-flash-realtime` 两个方向。每个连接需要指定目标语言，应用并行连接中文、法语目标，用实际识别出的源语言选择结果。录音只在开始监听后发送。连接失败后不重传未确认的语音，避免同一句被重复记入历史。[千问实时翻译接口](https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime)

机主要求「外放的声音的话把扬声器声音开的最低，耳机的话没关系」。实机只调机身媒体音量。应用按实际播放设备计算自己的播放增益，不修改其他应用或耳机的系统音量。普通分路可回退到系统的可用出口，手动指定接收耳机时选错出口则保持静音。
